# HotelFlow

**HotelFlow** — REST API-платформа для бронирования гостиничных номеров. Проект разработан на Java с использованием Spring Boot и предназначен для управления пользователями, номерами, бронированиями и отзывами.

Платформа поддерживает аутентификацию и авторизацию пользователей, проверку доступности номеров, управление бронированиями и хранение данных в PostgreSQL. Redis используется для управления жизненным циклом access-токенов и временного хранения OTP-кодов подтверждения регистрации.

## Возможности

- **Регистрация и авторизация** — создание аккаунта, вход в систему и подтверждение регистрации с помощью OTP-кода.
- **JWT-аутентификация** — использование access- и refresh-токенов.
- **Управление пользователями** — получение и обновление пользовательской информации.
- **Управление номерами** — получение информации о гостиничных номерах и их характеристиках.
- **Бронирование** — создание и управление бронированиями с проверкой доступности номеров.
- **Отзывы** — работа с отзывами пользователей.
- **Контроль доступа** — проверка прав пользователя и принадлежности ресурсов.
- **Автоматическое обновление статусов** — фоновая обработка истёкших бронирований.
- **Валидация данных** — проверка входящих запросов и обработка ошибок.
- **Документирование API** — Swagger UI и OpenAPI.
- **Контейнеризация** — запуск приложения и инфраструктурных компонентов с помощью Docker Compose.

## Архитектура

HotelFlow построен как монолитное Spring Boot-приложение с разделением ответственности между слоями.

```text
Client
  |
  v
REST Controllers
  |
  v
Services
  |
  +-------------------+
  |                   |
  v                   v
Repositories     Security Services
  |                   |
  v                   +------> Redis
PostgreSQL             |
                       v
                   JWT / OTP
```

### Основные слои

- **Controllers** — принимают HTTP-запросы, проверяют входные данные и формируют ответы.
- **Services** — реализуют бизнес-логику регистрации, авторизации, бронирования, работы с номерами и отзывами.
- **Repositories** — обеспечивают взаимодействие с PostgreSQL посредством Spring Data JPA.
- **DTO** — определяют структуру входящих запросов и исходящих ответов API.
- **Models** — представляют сущности предметной области.
- **Security** — отвечает за проверку JWT и управление доступом.
- **Exception handling** — обеспечивает централизованную обработку исключений.

Основные сервисы:

- `AuthenticationService`
- `UserService`
- `RoomService`
- `ReservationService`
- `ReviewService`

## Аутентификация и безопасность

В проекте используется Spring Security и JWT.

Основные механизмы безопасности:

- регистрация и подтверждение аккаунта с помощью OTP-кода;
- аутентификация по учётным данным;
- выдача access- и refresh-токенов;
- хранение и отзыв access-токенов с использованием Redis;
- хранение refresh-токенов в PostgreSQL;
- защита закрытых эндпоинтов;
- проверка принадлежности ресурсов пользователю;
- валидация входных данных;
- централизованная обработка ошибок доступа.

Пароли, секреты JWT и другие чувствительные данные не следует хранить в публичном репозитории. Для локального и production-окружений необходимо использовать соответствующую конфигурацию и переменные окружения.

## REST API

Основные группы эндпоинтов:

| Группа | Базовый путь | Назначение |
|---|---|---|
| Authentication | `/api/auth` | Регистрация, подтверждение аккаунта и вход |
| Reservations | `/api/reservations` | Создание и управление бронированиями |
| Reviews | `/api/reviews` | Работа с отзывами |
| Rooms | `/api/rooms` | Получение информации о номерах |

Фактический набор HTTP-методов, маршрутов и параметров определяется реализацией контроллеров.

## Запуск проекта

### Требования

- Java 21;
- Docker и Docker Compose;
- Git.

Maven Wrapper включён в проект, поэтому отдельно устанавливать Maven не обязательно.

### 1. Клонирование репозитория

```bash
git clone https://github.com/Yeaoke/HotelFlow.git
cd HotelFlow
```

### 2. Настройка окружения

Создай файл `.env` в каталоге `docker/`, если именно оттуда его ожидает твой Docker Compose.

Используй названия переменных, соответствующие конфигурации проекта. В ранее используемом окружении HotelFlow применялись:

```dotenv
POSTGRES_DB=reservation_info
POSTGRES_USERNAME=postgres
POSTGRES_PASSWORD=change_me

SECRET_KEY=replace_with_a_secure_secret

REDIS_HOST=localhost
REDIS_PORT=6379

PROFILE=dev
```

Это пример локальной конфигурации. Значения и переменные необходимо согласовать с `application.yml` и `docker-compose.yaml`. В частности, `POSTGRES_USERNAME` не является стандартной переменной инициализации официального образа PostgreSQL — для контейнера нужно проверить, как имя пользователя передаётся через Compose.

Не добавляй `.env` с секретами в Git.

### 3. Сборка проекта

Windows PowerShell:

```powershell
.\mvnw.cmd clean package
```

Linux / macOS:

```bash
./mvnw clean package
```

### 4. Запуск через Docker Compose

Если `docker-compose.yaml` находится в каталоге `docker/`, выполни из корня проекта:

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml up --build -d
```

Команда соберёт образ приложения и запустит сервисы, описанные в Docker Compose.

### 5. Проверка состояния контейнеров

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml ps
```

Просмотр логов приложения:

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml logs -f hotelflow
```

Остановка контейнеров:

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml down
```

Команда `down` по умолчанию не удаляет именованные тома базы данных.

## Конфигурация

Настройки приложения разделяются по окружениям с помощью профилей Spring.

Основные свойства приложения, используемые в конфигурации:

| Свойство | Назначение |
|---|---|
| `spring.datasource.url` | JDBC URL PostgreSQL |
| `spring.datasource.username` | Пользователь базы данных |
| `spring.datasource.password` | Пароль базы данных |
| `spring.data.redis.host` | Адрес Redis |
| `spring.data.redis.port` | Порт Redis |
| `security.jwt.secret_key` | Секрет для подписи JWT |
| `security.jwt.access_token_expiration` | Время жизни access-токена |
| `security.jwt.refresh_token_expiration` | Время жизни refresh-токена |

Переменные окружения, через которые задаются эти свойства, определяются конфигурацией приложения и Docker Compose. Их названия не обязательно совпадают с названиями свойств в `application.yml`.

Внутри Docker-сети приложение должно обращаться к PostgreSQL и Redis по именам соответствующих сервисов, а не через `localhost`.

## Тестирование

Запуск автоматизированных тестов:

Windows:

```powershell
.\mvnw.cmd test
```

Linux / macOS:

```bash
./mvnw test
```

Для тестирования используются JUnit 5 и Mockito.

Основные сценарии тестирования:

- регистрация и авторизация;
- подтверждение аккаунта и обработка неверного OTP;
- валидация запросов;
- обработка ошибок аутентификации и авторизации;
- создание бронирования;
- отказ при недоступности номера;
- проверка доступа к пользовательским ресурсам;
- создание и получение отзывов;
- обработка ошибок API.

## Деплой

Для развёртывания приложения необходимо:

1. Собрать Docker-образ.
2. Подготовить PostgreSQL и Redis.
3. Настроить переменные окружения и секреты.
4. Настроить сетевое взаимодействие между сервисами.
5. Обеспечить корректное создание и обновление схемы базы данных.
6. Запустить приложение и проверить логи.
7. Проверить основные API-сценарии после запуска.

Для production-окружения рекомендуется использовать HTTPS, безопасное управление секретами, резервное копирование базы данных и мониторинг приложения.
