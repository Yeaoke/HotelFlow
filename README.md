# HotelFlow

**HotelFlow** — REST API-платформа для бронирования гостиничных номеров. Проект разработан на Java с использованием Spring Boot и предназначен для управления пользователями, номерами, бронированиями и отзывами.

Платформа реализует аутентификацию и авторизацию пользователей, проверку доступности номеров, управление бронированиями и хранение данных в PostgreSQL. Redis используется для управления жизненным циклом access-токенов и временными данными подтверждения регистрации.

## Возможности

- **Регистрация и авторизация** — создание аккаунта, вход в систему и подтверждение регистрации с помощью OTP-кода.
- **JWT-аутентификация** — использование access- и refresh-токенов.
- **Управление пользователями** — получение и обновление пользовательской информации.
- **Управление номерами** — просмотр информации о гостиничных номерах и их характеристиках.
- **Бронирование** — создание и управление бронированиями с проверкой доступности номеров.
- **Отзывы** — работа с отзывами пользователей.
- **Контроль доступа** — ограничение операций в соответствии с правами пользователя и принадлежностью ресурсов.
- **Автоматическое обновление статусов** — фоновая задача для обработки истёкших бронирований.
- **Валидация данных** — проверка входящих запросов и обработка ошибок.
- **Документирование API** — Swagger UI и спецификация OpenAPI.
- **Контейнеризация** — запуск приложения и инфраструктурных компонентов с помощью Docker Compose.

## Архитектура

HotelFlow построен как монолитное Spring Boot-приложение с разделением ответственности между слоями.

```text
Client
  |
  v
REST Controllers
  |
  v
Services
  |
  +--------------------+
  |                    |
  v                    v
Repositories      Security Services
  |                    |
  v                    +------> Redis
PostgreSQL              |
                        v
                    JWT / OTP
```

### Основные слои

- **Controllers** — принимают HTTP-запросы, проверяют входные данные и формируют HTTP-ответы.
- **Services** — содержат бизнес-логику регистрации, авторизации, бронирования, работы с номерами и отзывами.
- **Repositories** — обеспечивают взаимодействие с PostgreSQL посредством Spring Data JPA.
- **DTO** — определяют структуру входящих запросов и исходящих ответов API.
- **Models** — представляют основные сущности предметной области.
- **Security** — отвечает за защиту API, проверку JWT и управление доступом.
- **Exception handling** — обеспечивает централизованную обработку исключений и формирование ответов об ошибках.

Основные функциональные компоненты:

- `AuthenticationService`
- `UserService`
- `RoomService`
- `ReservationService`
- `ReviewService`

## Аутентификация и безопасность

В проекте используется JWT для организации аутентификации.

Основные механизмы безопасности:

- регистрация и подтверждение аккаунта с помощью OTP-кода;
- аутентификация по учётным данным;
- выдача access- и refresh-токенов;
- хранение и отзыв access-токенов с использованием Redis;
- хранение refresh-токенов в PostgreSQL;
- защита закрытых эндпоинтов с помощью Spring Security;
- проверка принадлежности бронирований и других ресурсов пользователю;
- валидация входных данных;
- централизованная обработка ошибок доступа.

Секреты, пароли и другие чувствительные настройки должны передаваться через переменные окружения или защищённую конфигурацию окружения.

## REST API

Основные группы эндпоинтов организованы по функциональным областям.

| Группа | Базовый путь | Назначение |

Фактический набор HTTP-методов, маршрутов и параметров определяется реализацией контроллеров.

## Запуск проекта

### Требования

Для локального запуска необходимы:

- Java 21;
- Docker и Docker Compose;
- Git.

Maven Wrapper включён в проект, поэтому устанавливать Maven отдельно не обязательно.

### 1. Клонирование репозитория

```bash
git clone https://github.com/Yeaoke/HotelFlow.git
cd HotelFlow
```

### 2. Настройка переменных окружения

Создай файл `.env` в каталоге где запускается Docker Compose.

Пример переменных:

```dotenv
POSTGRES_DB=reservation_info
POSTGRES_USER=hotelflow
POSTGRES_PASSWORD=change_me

JWT_SECRET_KEY=replace_with_a_secure_secret
JWT_ACCESS_EXPIRATION=900000
JWT_REFRESH_EXPIRATION=604800000
```

Названия переменных необходимо согласовать с конфигурацией Spring Boot и `docker-compose.yaml`. Значения выше являются примером, а не готовыми производственными секретами.

Не добавляй `.env` в Git. Для production используй уникальные секреты и надёжное хранилище конфигурации.

### 3. Сборка проекта

В Windows:

```powershell
.\mvnw.cmd clean package
```

В Linux/macOS:

```bash
./mvnw clean package
```

### 4. Запуск через Docker Compose

Если `docker-compose.yaml` находится в каталоге `docker/`, выполни из корня проекта:

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml up --build -d
```

Команда соберёт образ приложения и запустит контейнеры приложения, PostgreSQL и Redis.

### 5. Проверка состояния контейнеров

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml ps
```

Просмотр логов приложения:

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml logs -f hotelflow
```

При успешном запуске приложение должно подключиться к PostgreSQL и Redis и завершить инициализацию Spring Boot без критических ошибок.

Остановить контейнеры:

```bash
docker compose --env-file docker/.env -f docker/docker-compose.yaml down
```

Команда `down` по умолчанию не удаляет именованные тома базы данных.

## Конфигурация

Настройки приложения разделяются по окружениям. Для production следует использовать отдельный профиль, например `prod`.

Основные параметры конфигурации:

| Параметр | Назначение |
|---|---|
| `SPRING_PROFILES_ACTIVE` | Активный профиль Spring |
| `SPRING_DATASOURCE_URL` | JDBC URL базы PostgreSQL |
| `SPRING_DATASOURCE_USERNAME` | Пользователь базы данных |
| `SPRING_DATASOURCE_PASSWORD` | Пароль базы данных |
| `SPRING_DATA_REDIS_HOST` | Адрес Redis |
| `SPRING_DATA_REDIS_PORT` | Порт Redis |
| `JWT_SECRET_KEY` | Секрет для подписи JWT |
| `JWT_ACCESS_EXPIRATION` | Время жизни access-токена |
| `JWT_REFRESH_EXPIRATION` | Время жизни refresh-токена |

Перечисленные имена являются ориентиром для конфигурации. При запуске нужно использовать именно те имена переменных и свойства, которые заданы в `application.yml`.

В Docker Compose приложения должны обращаться к PostgreSQL и Redis по именам соответствующих сервисов внутри Docker-сети, а не через `localhost`.

## Тестирование

Для запуска автоматизированных тестов:

```bash
./mvnw test
```

В Windows:

```powershell
.\mvnw.cmd test
```

В проекте используются JUnit 5 и Mockito для проверки поведения отдельных компонентов и контроллеров.

Рекомендуется проверять следующие сценарии:

- успешная регистрация и авторизация;
- подтверждение аккаунта и обработка неверного OTP;
- валидация запросов;
- обработка ошибок аутентификации и авторизации;
- создание бронирования;
- отказ при недоступности номера;
- проверка доступа пользователя к собственным ресурсам;
- создание и получение отзывов;
- корректная обработка ошибок API.

Успешная сборка и прохождение тестов должны подтверждаться результатами фактического запуска.

## Деплой

Приложение подготовлено к контейнеризированному запуску с использованием Docker.

Для развёртывания в production необходимо:

1. Собрать Docker-образ приложения.
2. Подготовить доступную PostgreSQL-базу данных.
3. Настроить Redis.
4. Передать переменные окружения и секреты.
5. Настроить сетевое взаимодействие между приложением и инфраструктурой.
6. Выполнить миграции или контролируемое обновление схемы базы данных.
7. Запустить приложение и проверить логи.
8. Выполнить проверку основных API-сценариев после запуска.

Для публичного развёртывания рекомендуется использовать HTTPS, безопасное управление секретами, резервное копирование базы данных и мониторинг состояния приложения.
